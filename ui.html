Files → groups

Tick to put a file in a group by hand. A file can feed several groups — two sheets of one workbook, say, each read by its own setup. Files from other folders stay in their groups when you browse elsewhere.

Steps run top to bottom and can use any group or any step above them. Formulas are the same Excel-style ones as Add columns; SQL is a SELECT over the tables by name (a name with spaces goes in "double quotes").

A relationship points from a detail table (many rows per key) to a lookup table (one row per key). Reports on the detail table can then use the lookup table's columns as Table.Column — in slicers, charts, pivots and filters — without a merge step. The lookup side is cut to one row per key, so totals never double.

Duplicates across all files

Looked for over every file of this group together — a ticket in January's extract and again in February's counts twice. It runs after each file's filters and columns, on the columns you keep; keys compare trimmed and ignoring case, and a blank key is never a duplicate.

Extra columns written after the ones you kept — stamp the period or source file, cut or join values, look codes up in a table you paste, flag duplicates, or write an Excel-style formula.

Look up specific values across every ticked file. Exact matching builds a hash set, so one ticket number and fifty thousand cost about the same.

Run parameters

Write {PERIOD} — or any name below — in a folder, a file rule, a filter value, a column's text, SQL, or the output's name and folder. It is filled in whenever the setup reads or runs: a fixed value, one asked for at each run, or a date worked out from today (yyyy-mm, MMMyy → JUL26, yyyy-Qq → 2026-Q3). From the command line: --set PERIOD=2026-09.

Checks

Worked out on the finished tables, before anything is written. A check set to Stop writes nothing when it fails; Warn writes and says so. Results show here and on the Result tab, go to a Checks sheet beside the output and to the run log; from the command line a stopped run exits with code 3.

Where it goes

What the run writes

Each group's ColSift work runs first — its columns, filters and added columns — then the Combine steps on those results, then everything ticked below is written in one go.

CSV / TXT: one file per table, named <file name>_<table>. A table past Excel's 1,048,575 rows carries on in a second sheet. Splitting by rows or by value, and one output per input file, apply to a setup with a single group.

Column formats

Text keeps values exactly as extracted, leading zeros and all. Number and Date write real Excel numbers and dates — and format them in CSV. A value that doesn't read as one stays as text, and the run says how many.

PDF reports

Written beside the data from the same numbers as the Analysis tab — separate from the sheets above, so you can have either or both. PDFs use the built-in Helvetica font, which covers Western European text; other scripts (Arabic, Cyrillic …) print as “?” — the Excel output carries every character.
